<Section title="Background and Motivation" kind="context">

Online banking increases the amount of customer data that is available for credit assessment. Lenders must assess potential borrowers and make credit decisions with reliable methods.

Machine learning can use this data to support credit decisions. It does not replace a full credit assessment.

</Section>

<Section title="Problem Statement" kind="context">

> Can machine learning classification models accurately predict a person's credit rating?

<Section title="Methodology: Google Data Analytics Framework" highlight="Methodology" kind="theory">

The project follows the phases of the Google Data Analytics framework. The first phase, Ask, is the Problem Statement above. The other five phases are Prepare, Process, Analyse, Share and Act.

### 1. Prepare

The training and test CSV files were loaded and combined into one pandas DataFrame for data preparation and analysis.

The test file has no `Credit_Score` labels. Thus, all its rows were removed when rows without a label were removed (Process, step 2). All models therefore use records from the training file only. Each model has its own split into a training set and a test set (Process, step 10).

### 2. Process

1. **Check completeness.** Find the number of missing values in each column.
2. **Remove missing values.** Remove rows that have no `Credit_Score`. After type conversion, remove all rows that still have a missing value.
3. **Convert data types.** Some numeric columns contain text errors. Convert them to numbers with coercion, which changes values that are not valid numbers to missing values. Change `Credit_History_Age` from text (for example, "22 Years and 1 Months") to whole years. Change `Occupation`, `Payment_of_Min_Amount` and `Payment_Behaviour` to dummy variables, which are 0/1 columns, one for each category.
4. **Remove invalid values and outliers.** Remove impossible values, such as a negative age, an age of 100 or more, or a negative number of loans. Then remove rows above an upper limit of median + 5 × IQR for seven features with extreme values. IQR is the interquartile range.
5. **Describe the data.** Calculate descriptive statistics. Examine the distribution of each numeric variable (Figures 1 and 2).
6. **Find multicollinearity.** Make a correlation matrix (Figure 3). Multicollinearity occurs when two or more features have a strong linear relationship. `Annual_Income` and `Monthly_Inhand_Salary` have a correlation of 1.0, so `Annual_Income` was removed from the binary models.
7. **Remove fields that the prediction does not need.** Remove `ID`, `Customer_ID`, `Month`, `Name` and `SSN`. Also remove `Type_of_Loan`, which has too many category combinations, and `Credit_Mix`, which is very similar to the target.
8. **Make one dataset for each task.** The binary dataset has 21,740 records. The three-class dataset has 51,038 records.
9. **Prepare the targets.** For logistic regression and the perceptron, Poor = 0 and Good = 1. These models do not use the Standard category. For the decision tree, Poor = 0, Standard = 1 and Good = 2.
10. **Split the data.** The binary models use a random 70/30 split into training and test sets (6,522 test records). Each binary model has its own random split, so the test sets are not identical. The decision tree uses a stratified 75/25 split (12,760 test records).

The binary models do not use the Standard category, so they cannot classify a Standard customer. Standard is the largest category: 27,373 of the 51,038 records in the three-class dataset. To separate Poor from Good is also an easier task than to separate three classes. Thus, binary results and three-class results are not directly comparable.

### 3. Analyse

The models were evaluated with confusion matrices and classification metrics. A confusion matrix compares the actual class of each test record with the predicted class.

For a binary model, one class is the positive class. The other class is the negative class. In this project, Good is the positive class for the ROC curve. A classification report calculates precision, recall and F1-score for each class in turn, with that class as the positive class.

The four cells of a confusion matrix are:

- **TP (true positive).** The record is positive and the model predicts positive.
- **TN (true negative).** The record is negative and the model predicts negative.
- **FP (false positive).** The record is negative, but the model predicts positive.
- **FN (false negative).** The record is positive, but the model predicts negative.

"True" or "False" tells if the prediction is correct. "Positive" or "Negative" is the predicted class.

The scikit-learn plots in this write-up show class 0 in the first row and column. With Good (1) as the positive class, the bottom-right cell is TP and the top-left cell is TN.

**Accuracy** is the proportion of all predictions that are correct.

$$
\text{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN}
$$

Use accuracy when both classes are important and the classes are approximately balanced. When one class is much more common, accuracy can be misleading. A model that always predicts the common class can have a high accuracy.

**Precision** is the proportion of positive predictions that are correct.

$$
\text{Precision}=\frac{TP}{TP+FP}
$$

Use precision when a false positive has a high cost.

**Recall** is the proportion of actual positive cases that the model finds.

$$
\text{Recall}=\frac{TP}{TP+FN}
$$

Use recall when a false negative has a high cost and the model must find as many positive cases as possible.

**F1-score** is the harmonic mean of precision and recall.

$$
F1=2\,\frac{\text{Precision}\times\text{Recall}}{\text{Precision}+\text{Recall}}
$$

Use F1-score when precision and recall are both important and one summary value is useful.

**Specificity** is the proportion of actual negative cases that the model identifies correctly.

$$
\text{Specificity}=\frac{TN}{TN+FP}
$$

Use specificity when the correct identification of negative cases is important.

These metrics have trade-offs. If the decision threshold changes so that the model predicts the positive class more often, recall usually increases and precision usually decreases. The best metric depends on the cost of each type of error. For a lender, an FP can be a loan to a high-risk customer. An FN can be a refusal to a good customer.

### Logistic Regression

#### Theory

Logistic regression estimates the probability of a binary outcome from input features. The process has four steps:

1. The model calculates a weighted sum of the input features, $z = b + \boldsymbol{\beta}^{T}\mathbf{x}$. Here, $b$ is the intercept, $\boldsymbol{\beta}$ is the vector of coefficients and $\mathbf{x}$ is the vector of input features. The value $z$ is the log-odds of class 1.
2. It applies the sigmoid function to $z$.
3. The sigmoid function changes $z$ to a probability between zero and one.
4. A decision threshold changes the probability to a predicted class. If the probability is equal to or more than the threshold, the model predicts class 1. The threshold can be adjusted. For example, with a threshold of 0.9, the model classifies a record as Good only if the predicted probability of Good is 0.9 or more. This project used the scikit-learn default threshold of 0.5.

$$
\sigma(z)=\frac{1}{1+e^{-z}}
$$

<Figure src={logisticDiagram} width={570} height={306} label="Figure 4" narrow alt="Diagram that compares a straight blue line, the linear model y = b0 + b1 x, with an orange S-shaped curve, the logistic model p = 1 / (1 + e^-(b0 + b1 x)). The straight line goes below 0 and above 1. The S-curve stays between 0 and 1.">
A linear model can predict values below 0 or above 1. The logistic model keeps the output between 0 and 1, so it can be a probability.
</Figure>

Training finds the values of $b$ and $\boldsymbol{\beta}$ that minimise binary cross-entropy, also called log loss. Here, $y_i$ is the actual class (0 or 1) and $p_i$ is the predicted probability of class 1 for record $i$ of $n$:

$$
L=-\frac{1}{n}\sum_{i=1}^{n}\left[y_i\log(p_i)+(1-y_i)\log(1-p_i)\right]
$$

Log loss gives a large penalty to a confident prediction that is wrong. It is not the same as the mean squared error, which linear regression usually minimises. There is no closed-form solution, so the training uses an iterative optimisation method. In this case, the scikit-learn `liblinear` solver was used.

**Regularisation** adds a penalty to the loss. The penalty makes large coefficients less likely and can reduce overfitting. In scikit-learn, the parameter $C$ is the inverse of the penalty strength $\lambda$: a smaller $C$ gives a stronger penalty.

- **L1 (Lasso) regularisation** adds a penalty based on the absolute values of the coefficients, $\lambda\sum_j |\beta_j|$. It can make some coefficients exactly zero. Thus, it can reduce model complexity and help select features.
- **L2 (Ridge) regularisation** adds a penalty based on the squared coefficients, $\lambda\sum_j \beta_j^2$. It makes coefficients smaller but usually not zero.

#### Implementation

The first experiments used four simple logistic regression models, LR1 to LR4. Each model has one independent variable. Their test accuracies were between 0.69 (salary) and 0.79 (interest rate).

LR2, delay from due date: the probability decreases to near zero at 40 days. LR3, outstanding debt: the probability decreases to near zero at about 3,000 USD. LR4, interest rate: the probability decreases quickly to near zero at about 20%.">
Four simple logistic regressions, each fitted to one feature. The red curve is the predicted probability of a Good rating.
</Figure>

Next, a model with all features was trained. `Annual_Income` and `Monthly_Inhand_Salary` are perfectly correlated, and this made the coefficients unstable. `Annual_Income` was removed. All features were standardised (scaled to a mean of 0 and a standard deviation of 1).

L1 regularisation was then used to find features with small effects. **Grid search with cross-validation** selected the value of $C$:

- Grid search tests a defined set of hyperparameter values. A hyperparameter is a setting that is chosen before training.
- Cross-validation divides the training data into $k$ parts, called folds.
- The model is trained on $k-1$ folds and validated on the remaining fold. This repeats until each fold has been the validation fold once.
- The selected value has the best mean score on the validation folds.

The L1 search tested 100 values of $C$ from $10^{-5}$ to $10^{0.5}$, with 3-fold cross-validation and accuracy as the score. The best value was $C \approx 0.245$, with a mean cross-validation accuracy of 0.848.

The L1 coefficients and the p-values of a statsmodels logistic regression were then used to select features. The occupation features were not statistically significant, so they were removed. The final model uses 15 features: `Monthly_Inhand_Salary`, `Outstanding_Debt`, `Num_Credit_Card`, `Interest_Rate`, `Num_of_Delayed_Payment`, `Delay_from_due_date`, `Num_of_Loan`, two `Payment_of_Min_Amount` dummy variables and six `Payment_Behaviour` dummy variables.

The final model uses **L2 regularisation**, because all 15 features were kept. A second grid search tested 100 values of $C$ from $10^{-5}$ to $10$, with 5-fold cross-validation and accuracy as the score. The best value was $C \approx 0.351$, with a mean cross-validation accuracy of 0.841. The final model uses unscaled features.

### Perceptron

#### Theory

<Figure src={perceptronDiagram} width={1050} height={568} label="Figure 8" alt="Perceptron diagram. A bias input b and inputs X1 to Xn connect through weights w1 to wn to one unit. The unit calculates z = b + the sum of wi xi, then applies a threshold function f(z). The output y is 1 or 0. The error y − ŷ gives a weight change Δw = α(error)xk, and the weights are updated as wk+1 = wk + Δwk.">
A perceptron. The unit calculates a weighted sum of the inputs, applies a threshold function and uses the error to update the weights.
</Figure>

A perceptron is a simple neural model with one computational unit. It multiplies each input feature by a learned weight, adds a bias and applies an activation function:

$$
z=\mathbf{w}^{T}\mathbf{x}+b
$$

$$
\hat{y}=f(z)=\begin{cases}1 & \text{if } z>0\\ 0 & \text{otherwise}\end{cases}
$$

The activation function changes $z$ into the output of the unit. A classic perceptron, as in this project, uses a threshold (step) function. Multilayer neural networks often use other activation functions. Examples are ReLU in hidden layers, sigmoid for a binary output and softmax for a multi-class output. The weights show how much each feature contributes to $z$, and thus to the decision boundary.

This project uses the scikit-learn `Perceptron`. It trains with stochastic gradient descent (SGD), one record at a time, on the perceptron loss. With the classes written as $y_i \in \{-1, +1\}$, the loss for a record is:

$$
L_i=\max\left(0,\,-y_i z_i\right)
$$

The loss is zero for a correct prediction. For a wrong prediction, the weights change:

$$
\mathbf{w} \leftarrow \mathbf{w} + \eta\, y_i\, \mathbf{x}_i, \qquad b \leftarrow b + \eta\, y_i
$$

The learning rate $\eta$ (`eta0` in scikit-learn) controls the size of each update. Figure 8 shows the same rule for classes 0 and 1: $\Delta w = \eta(y-\hat{y})x$. The diagram uses the symbol $\alpha$ for the learning rate. In scikit-learn, `alpha` is the regularisation strength. Training stops after `max_iter` passes over the data, or when the loss improves by less than `tol`.

#### Implementation

The first perceptron used all 39 features of the binary dataset, with L1 regularisation. L1 regularisation pushes weights to zero, so it can help select features.

Grid search with 2-fold cross-validation and accuracy as the score selected the hyperparameters.

Some weights in this model were zero, for example most of the occupation features. A feature with a zero weight does not contribute directly to the linear decision function. A non-zero weight does not prove that a feature is important in general. The features were not standardised, so the size of a weight also depends on the scale of its feature.

After this step, a subset of 29 features was selected and used to train the perceptron with no regularisation penalty. This final model used manually set hyperparameters, not the grid search values.

### Decision Tree

#### Theory

<Figure src={treeDiagram} width={275} height={387} label="Figure 10" narrow alt="Decision tree diagram. A root node splits on Yes and No into two internal nodes. One internal node tests Age ≤ 30 and the other tests Income > 50k. Each test leads to two leaf nodes that give Class A or Class B.">
Parts of a decision tree: the root node, internal nodes that test features, and leaf nodes that give a class.
</Figure>

A decision tree makes a prediction with a sequence of rules. Each internal node tests a feature. Each branch is one outcome of the test. A leaf node gives the predicted class.

The tree uses Gini impurity to measure how mixed the classes are in a node:

$$
G=1-\sum_{k=1}^{K}p_k^2
$$

Here, $p_k$ is the proportion of class $k$ in the node, and $K$ is the number of classes. A Gini impurity of zero means that all samples in the node are in one class. A higher value shows a greater mixture of classes.

At each node, the algorithm evaluates the possible splits and selects the split that gives the largest decrease in impurity. This method is greedy: it selects each split for its immediate improvement only. Thus, it does not guarantee the best possible tree.

#### Implementation

The decision tree uses three target classes:

- Poor = 0
- Standard = 1
- Good = 2

After cleaning, the three-class dataset has 51,038 records. The class counts for the full dataset, before the split, are:

- Class 0 (Poor): 14,933
- Class 1 (Standard): 27,373
- Class 2 (Good): 8,732

The split into training and test sets is stratified. Stratified sampling keeps the class proportions the same in the training set and the test set. This makes the test results more reliable. Stratification does not correct class imbalance. Standard is still more than half of each set.

The first tree used the scikit-learn default hyperparameters on all 42 features. It has a depth of 38 levels and 7,354 leaf nodes (Figure 11). A tree of this size is difficult to interpret and can overfit, because it can learn details of the training data that do not apply to new data.

<Figure src={defaultTree} width={1000} height={1000} label="Figure 11" alt="A very large decision tree with thousands of small coloured nodes in dense rows. The individual nodes and their labels are too small to read.">
The default tree: 38 levels and 7,354 leaf nodes.
</Figure>

Grid search with 2-fold cross-validation was then used to tune the tree. The search tested these controls:

- **Maximum depth** (`max_depth`): the maximum number of levels.
- **Maximum features** (`max_features`): the number of features considered at each split.
- **Maximum leaf nodes** (`max_leaf_nodes`).
- **Minimum impurity decrease** (`min_impurity_decrease`): the smallest decrease in impurity that a split must give.
- **Minimum samples** per leaf (`min_samples_leaf`) and per split (`min_samples_split`).
- **Cost-complexity pruning** (`ccp_alpha`): a penalty that removes branches that add little.

The tuned tree used all 42 features, a maximum depth of 10, 15 features at each split, a maximum of 20 leaf nodes, at least 10 samples in each leaf and `ccp_alpha` = 0.0001. Table 5 shows its results.

Feature importance measures how much each feature decreases impurity across all the splits in the fitted tree. The feature importance values were used to select 11 features. A second grid search tuned a final tree on these 11 features. The final tree has a depth of 8 and 20 leaf nodes (Figure 12).

<Section title="Lessons Learnt" kind="context">

### Bias–variance trade-off

A model that is too simple underfits: it does not learn the pattern in the data. A model that is too complex overfits: it learns details of the training data that do not apply to new data. The default decision tree, with 7,354 leaf nodes, is an example of a complex model. Limits on model complexity and validation on data that the model has not seen help to balance these risks.

### Hyperparameter optimisation

Grid search can need much computation, because it trains a model for each combination of values and each fold. For example, the perceptron search tested more than 14,000 combinations. Other methods, such as Bayesian optimisation, use the results of earlier evaluations to select the next values. In some cases, these methods need fewer evaluations to find good values. They do not guarantee a better model.

### Feature scaling

Features with different numeric scales can affect some machine learning algorithms. Scaling is important for methods such as logistic regression and perceptrons, when their optimisation or regularisation is sensitive to scale. The final perceptron used unscaled features, so its weights are difficult to compare. Scaling is not necessary for every model. Decision trees usually do not need feature scaling, because each split uses one feature at a time.
