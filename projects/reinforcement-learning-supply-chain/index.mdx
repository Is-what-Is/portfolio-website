<Section title="Summary" kind="context">

This research tests if reinforcement learning (RL) can make adaptive decisions in a supply chain with disruptions. A Deep Q-Network (DQN) agent chose a supplier allocation, a delivery route and a safety stock each simulated day. I compared it with fixed, random and rule-based policies.

- The DQN had the highest fill rate and the lowest backlog in the reported scenario. The rule-based policy had a better reward.
- On an unseen scenario, the DQN did much better than the fixed and random policies, but not as well as the rule-based policy.
- The agent showed signs of reward hacking and changed actions frequently. Reward design is the main weakness.
- RL can help with specific supply chain decisions. It needs optimisation, classical machine learning, rule-based methods, explainability and human oversight alongside it.

</Section>

<Section title="Background and Motivation" kind="context">

I have three years of experience in digital solutions for logistics. My company develops logistics control tower software with digital twin capabilities. This project explores if RL can add useful decision support to that type of software.

Adaptive decisions matter most in complex, disruption-prone industries such as construction, defence and manufacturing. This project is a research proof of concept, not a deployed product.

</Section>

<Section title="Problem Statement" kind="context">

Supply chains are difficult for RL:

- **Delayed rewards.** The effect of a decision can appear days or weeks later.
- **Different timescales.** Processes run hourly, daily and weekly.
- **Limited data.** Real disruptions are rare, so historical data has few examples to learn from.
- **Interpretability.** Deep RL policies are difficult to explain and validate.

This project addresses the data problem with simulation. The other challenges remain open.

> Can a simplified supply chain simulation demonstrate that reinforcement learning can support supply chain management decisions and adapt to operational disruptions?

</Section>

<Section title="Data" kind="implementation">

No external dataset was used. A stochastic simulation generated all training and evaluation data. Simulation gives the agent many repeatable disruptions, which real records cannot supply.

</Section>

### Reinforcement learning architecture

<Figure src={dtArchitecture} width={1280} height={720} label="Figure 2" alt="Architecture diagram. The managed system, the supply chain simulation, produces state through probes and applies actions through effectors for safety stock, supplier allocation and delivery route. The managing system, the DQN agent, contains a Q-network, a target Q-network, a DQN loss and an experience replay memory, labelled with the Monitor, Analyse, Plan, Execute and Knowledge stages of a MAPE-K loop.">
The digital twin architecture: the DQN agent monitors the simulation, selects actions and learns from stored experience, in a MAPE-K loop.
</Figure>

The agent trained for 2,500 episodes. Each episode used a random scenario from 0 to 7: the no-disruption baseline and seven disruption scenarios. I then compared the agent with three policies on all scenarios, including the unseen scenario 8:

- **Fixed:** always the same action. It sets a lower bound.
- **Random:** a random action each day.
- **Rule-based:** reads the true disruption parameters and applies the correct response. It sets the target to beat.

<Section title="Theoretical Foundations" kind="theory">

### Markov decision process

The agent and the simulation interact in a loop. The agent observes the **state**: the current supply chain data. It selects an **action**. The simulation moves forward one day and returns a **reward** and the **next state**. The agent learns which actions give the highest total reward over time.

### Reward function

The reward function defines the objective used to train the agent:

$$
r_t = 100 \cdot \text{FillRate}_t - 2 \cdot \text{NSAmp}_t - 0.5 \cdot B_t - 0.1 \cdot I_t
$$

### Bellman equation

The value of an action is its immediate reward plus the discounted value of the best next action:

$$
Q^*(s,a) = \mathbb{E}\left[r + \gamma \max\nolimits_{a'} Q^*(s',a') \;\middle|\; s,a\right]
$$

### Deep Q-Network

A DQN uses a neural network to estimate the value of each action in the current state. The agent stores its experience from the simulation and uses it to improve these estimates. During training, the network updates its weights to make its estimates more accurate. A second target network, which updates less often, keeps learning stable. The agent then selects the action with the highest estimated future reward.

</Section>

<Section title="Discussion and Limitations" kind="results">

<Figure src={policyActions} width={2086} height={1768} label="Figure 5" alt="Three step-chart panels over 365 days comparing the actions of the rule-based and DQN policies under scenario 5: supplier split alpha, route and safety stock. The rule-based policy changes only at the disruption boundaries, while the DQN switches between values many times throughout the year, including before any disruption begins.">
Daily actions of the rule-based policy and the DQN under scenario 5: the DQN changes action much more often.
</Figure>

- **Reward hacking.** The DQN showed signs of reward hacking and frequent action switching. The reward function needs more work, for example a penalty for switching.
- **Interpretability.** A deep neural network does not explain why the agent selects a particular action.
- **Simulation limitations.** The single-echelon supply chain is a simplified proof of concept. Its results do not show performance in a real supply chain.
- **Future research.** Targeted supply chain applications, multi-agent RL where appropriate, alternative algorithms such as PPO, explainable AI and human oversight.

</Section>

<Section title="Lessons Learned" kind="context">

RL can be useful for specific supply chain decisions, but one approach is unlikely to manage an entire supply chain. The better approach is to combine RL with classical machine learning, optimisation and rule-based methods, each where it fits. When deep learning makes operational decisions, explainability and human oversight are essential. For logistics control tower and digital twin software, I see the opportunity in targeted, explainable decision support, not a fully autonomous controller.

</Section>
